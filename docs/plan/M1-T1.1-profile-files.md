# T1.1 Profile the DLD files

**Goal:** know exactly what columns each DLD file has before any importer is written.

**Read first:** `CLAUDE.md`, `pipeline/src/dpi/profile.py`, `docs/datasets.md`.

**Inputs:** the files the owner uploads (expected: Transactions, Rent Contracts, Registered Freehold Units,
Projects, Land Registry; CSV or XLSX). Copy them to `data/raw/<YYYY-MM-DD>/` (never committed).

## Steps
1. If a file is XLSX, convert it to CSV first (add `openpyxl` to the pipeline's dev deps if needed).
2. For each file run `dpi profile data/raw/<date>/<file>.csv --title "<Dataset name>"` and paste the output
   into `docs/datasets.md` under a heading per dataset, with the download source and date.
3. Answer the open questions at the top of `docs/datasets.md`, citing the column names:
   - Units file: is there a floor column? a unit number? a building id?
   - Sales/rents: is there a land number, project number or building id that links to other files?
4. Add a short **Linking keys** section: which columns join which files.

## Checks
- `docs/datasets.md` has one section per file and no personal values (the profiler hides them; double-check).
- `cd pipeline && .venv/bin/pytest -q` passes.

## Findings

unit numbers exist; sales link to units through `project_number`; rent contracts have no building name; no file
