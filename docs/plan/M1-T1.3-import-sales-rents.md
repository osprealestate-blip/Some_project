# T1.3 Import sales and rent contracts

**Goal:** all DLD sales and rent contracts for Dubai are in `transactions` and `rent_contracts`, cleaned,
with `community_id` set.

**Depends on:** T1.1 (column names known), T1.2 (communities loaded).

**Read first:** `CLAUDE.md`, `docs/datasets.md`, `db/migrations/0001_init.sql` (transactions,
rent_contracts).

**Reference (read-only, copy logic):** osp-crm `backend/app/services/market_transactions.py`:
header aliases (`_FIELDS`), sq m -> sq ft (x 10.7639), junk-row rules (MIN_SIZE_SQFT = 10 sq m,
MIN_SALE_PRICE = 50,000, MIN_ANNUAL_RENT = 5,000), dedupe key (source, source_ref).

## Steps
1. `pipeline/src/dpi/importers/dld.py`: read CSV in chunks, map headers through aliases, convert units,
   set `excluded` to the rule name for junk rows instead of dropping them.
2. Resolve `raw_area` to `community_id` through the communities' official and common names.
   Unmatched names go to a report, not into a guess.
3. Keep `raw_building` and `raw_project` exactly as in the file; matching happens in T1.4/M2.
4. Never read or store buyer, seller, owner or tenant fields, even if the file has them.
5. CLI: `dpi import-dld --kind sale|rent <file> --source-date YYYY-MM-DD`; prints counts loaded, excluded
   by rule, and unmatched areas.
6. Tests with small fixture CSVs in `pipeline/tests/fixtures/` (made-up rows, no real personal data).

## Checks
- Import runs end to end on the real files; counts printed and copied into Findings.
- Re-running the same file changes no row counts (upsert works).
- `.venv/bin/pytest -q` passes.
