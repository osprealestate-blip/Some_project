# T1.2 Load communities into the database

**Goal:** the `communities` table holds all 234 polygons, with the common name and `is_launch` set.

**Read first:** `CLAUDE.md`, `db/migrations/0001_init.sql` (communities table), `web/lib/communities.ts`,
`docs/datasets.md` (bundled files section).

**Reference (read-only, copy logic):** osp-crm `backend/app/services/community_map.py`, the `_ALIASES`-style
mapping from official names to common names (e.g. "marsa dubai" -> "Dubai Marina",
"al barsha south fourth" -> "Jumeirah Village Circle (JVC)").

## Steps
1. Add `pipeline/src/dpi/db.py`: connect with `DATABASE_URL` from the environment (psycopg 3).
2. Add `pipeline/src/dpi/communities.py`:
   - `COMMON_NAMES`: official name (lower case) -> common name, ported from osp-crm.
   - `load(conn, geojson_path)`: upsert one row per feature on `dm_code` (OSM features have no code: use
     `name_official` as the key for those), geometry via `ST_Multi(ST_GeomFromGeoJSON(...))`,
     `is_launch` true for codes 392, 681, 346.
3. Add a CLI command `dpi load-communities [--path web/public/data/dubai_communities.geojson]`.
4. Tests in `pipeline/tests/test_communities.py` for the name mapping (no database needed).

## Checks
- `docker compose up -d db`, apply migrations, run the command: `select count(*) from communities` = 234,
  `select count(*) from communities where is_launch` = 3.
- `.venv/bin/pytest -q` passes.
